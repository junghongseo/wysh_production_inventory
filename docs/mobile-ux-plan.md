# 모바일 화면 개선 계획 (2026-11-27 점검)

375×812(아이폰 기준) 화면에서 모든 탭과 주요 모달을 실제 데이터로 열어 본 결과입니다.
점검은 운영 DB를 읽기만 한 로컬 복사본으로 했고, 저장은 막아 둔 상태였습니다.

## 점검 결과 요약

| 화면 | 문제 | 심각도 |
|---|---|---|
| 공통 상단 | 첫 화면 전체(약 750px)가 로고·테마·계정·통계·메뉴. 실제 내용은 스크롤해야 보임 | 높음 |
| 공통 메뉴 | 7개 메뉴가 3열 큰 버튼 격자로 상단에 있어 엄지가 닿지 않고, 화면 이동 때마다 위로 올라가야 함 | 높음 |
| 생산 일정 | 달력이 650px 고정이라 한 화면에 3일만 보이고 가로 스크롤. 일정 이름이 "11...", "발효 |..."로 잘림 | 높음 |
| 생산 일정 | "선택 차수" 안내가 이전/오늘/다음 버튼과 겹침 | 중간 |
| 생산 일정 | 일정을 누르면 상세가 달력 아래 멀리 열림 | 중간 |
| 배합표(드로어) | 화면 높이를 다 쓰지 않고, 표의 **필요량 열이 잘려** 핵심 숫자가 안 보임 | 높음 |
| 재고 | 9열 표(820px)를 가로 스크롤. 한 화면에 2열만 보임 | 높음 |

| 주문 분석 | 표가 가로로 넘침, 차트 범례 작음 | 낮음 |

괜찮았던 것: 로그인 화면, 리포트 작성 폼, AI 매니저 대화창(하단 시트), 앱 설정 모달, 입력칸 글자 크기(16px → 아이폰 확대 없음).

## 개선 계획

### 1단계 — 바로 고칠 것 (깨짐·가림, 위험 낮음)
1. 팀원 관리 카드: 모바일에서 버튼을 이름 아래 줄로 내림
2. 주문 정리: 가로 넘침 제거, 날짜 버튼 줄은 가로 스크롤로 정리
3. 배합표 드로어: 모바일에서 화면 전체 높이, 표는 원료명·필요량을 먼저 보이게(비율은 작게 또는 둘째 줄)
4. 모달·드로어가 열리면 AI 버튼 숨김, 닫기 아이콘 색 수정
5. 달력 머리의 "선택 차수" 안내 겹침 수정

### 2단계 — 화면 구조 (사용성 핵심) · 2026-11-28 구현

구현 메모: 모바일 전용 스타일은 `src/mobile.css`, 폭 판정은 `src/hooks/useIsMobile.js`(768px). 팀원 관리·앱 설정·테마 전환은 상단 계정 메뉴(`MobileAccountMenu`)로 옮김. 생산 일정은 고른 날(기본 오늘)부터 7일 목록 + 일정 상세 하단 시트.
6. **모바일 상단 축소 + 하단 탭바**: 상단은 로고·계정 메뉴만 한 줄. 메뉴는 화면 아래 고정 탭바(엄지 영역). 통계 카드는 접거나 한 줄 요약, 테마 버튼은 설정으로 이동
7. **생산 일정 모바일 보기**: 기본은 날짜별 목록(이번 주/선택한 날), 월간 달력은 점으로 일정 표시만. 일정 상세는 하단 시트로 열기
8. **재고 표 → 카드 목록**: 차수·제품·현재 재고·작업 버튼만 카드에, 나머지는 펼치기
9. **레시피 설정**: 제품을 누르면 편집 화면으로 전환(뒤로 가기로 목록 복귀)
10. 리포트 이력 이중 스크롤 제거

### 3단계 — 다듬기 · 2026-11-28 구현

구현 메모: 모바일 기준 글자 크기를 17px로 올려 rem 기반 인라인 글자를 한 번에 키움(12px 미만 글자 0개). 아이콘 버튼·입력칸 44px, 숫자 칸 전부 `inputMode="decimal"`. 주문 분석 표는 짧은 머리글·MM-DD 날짜, 추이 차트는 축 글자 확대·점 숫자 숨김. 리포트 제출 버튼 하단 고정, 모달 하단 안전 여백. 출고 히스토리 스크롤 상자 250px → 화면 높이 65%.
11. 글자 크기 기준: 본문 14px 이상, 보조 12px 이상. 버튼 터치 영역 44px
12. 주문 분석 표·차트 모바일 축약
13. 숫자 입력칸 숫자 키패드(`inputmode`), 긴 폼의 저장 버튼 하단 고정, 아이폰 하단 여백(safe-area)

PC 화면은 그대로 둡니다. 모든 변경은 모바일 폭(768px 이하)에만 적용합니다.

## 2-B와의 순서

- 이 개선은 화면 코드만 바꾸고 DB·동기화·권한 로직은 건드리지 않습니다. 2-B와 서로 막지 않습니다.
- 새 버전 자동 감지가 배포되어 있어서, 화면 배포 때마다 팀원 기기를 따로 챙길 필요가 없습니다. 이후 빌드는 모두 2-A를 포함하므로 2-B 조건(이전 빌드 0)에도 영향이 없습니다.
- 다만 **지금 DB는 공개 키만으로 모든 업무 데이터(배합 비율, 보고서, 단가표 등)를 읽을 수 있는 상태**입니다. 점검용 데이터도 로그인 없이 그대로 읽혔습니다. 화면 개선을 이유로 2-B를 미룰 이유는 없습니다.
- 권장: **2-B는 계획대로 먼저(영업 종료 후)**. 같은 날 저녁에 큰 화면 배포를 겹치지 않아야 문제가 생겼을 때 원인을 바로 가를 수 있습니다. 모바일 1단계는 2-B 다음 날 영업 중 배포, 2·3단계는 순서대로.
